## 친근한 UI 디자인 결정 (본 회차 핵심)

사용자 피드백: "사람이 친근하게 접근할 수 있도록 도형도 이쁘게".

OpenCV 기본 도형은 직각 모서리·flat 채움이라 사무적인 느낌. 친근함을 위해 다음 헬퍼·컴포넌트를 신설:

| 헬퍼/컴포넌트 | 기법 |
|---|---|
| `_draw_rounded_rect_fill` / `_outline` | cv2.rectangle 2개 + cv2.circle 4개 (채움) / cv2.line 4개 + cv2.ellipse arc 4개 (외곽) — 직접 합성 |
| `draw_rounded_panel(p1, p2, alpha, radius, outline)` | 위 두 헬퍼 + addWeighted로 반투명 카드 |
| `draw_soft_shadow` | 카드 뒤 둥근 어두운 패널 offset 5px, alpha 0.45 |
| `draw_color_dot(center, radius, color, highlight=True)` | 큰 둥근 색 원 + **좌상단 흰 광택** — 친근함의 핵심 |
| `draw_progress_dots(cx, y, collected, goal)` | 채워진 윈 색 점 + 빈 회색 점 — `3/5` 텍스트보다 직관적 |
| `_draw_medal(center, outer, inner)` | 우승 시 큰 둥근 메달 (원 3겹 + 광택) |
| `draw_rounded_object_box(bbox, color, radius=10)` | YOLO 박스의 둥근 모서리 버전 — 흰 외곽선 옵션 |

**적용 화면**:
- 난이도 선택: 둥근 다크 카드 + 색 배지(1/2/3) + 핑크 외곽 (`draw_hunt_difficulty_select`)
- READY (미션 카드): 큰 둥근 색 원 + 색 이름 + 진행 점 미리보기 + SPACE 안내
- HUD: 둥근 패널 안에 좌(색 원 + 한글) / 중(진행 점) / 우(남은 시간)
- PLAYING: 객체 박스를 둥근 모서리로, 매칭 객체는 굵은 색 + 흰 외곽 + 좌상단 색 점 뱃지
- GAME_OVER: 우승 시 메달 + 핑크 외곽 카드; 실패 시 색 원 + LOSE 색 카드

## W5 트러블슈팅

### 문제 17 (신규): 다른 게임이 같은 모듈명 `score_tracker.py`를 가져 pytest 통합 실행에서 import 충돌

**증상**: `.venv/bin/pytest games/07_speed_counter/tests/ ... games/11_color_hunt/tests/`를 함께 실행했더니 `ImportError: cannot import name 'END_TOO_MANY_FAILS' from 'score_tracker' (/home/gjkong/PlayWait/games/11_color_hunt/src/score_tracker.py)` — W2의 `test_score_tracker.py`가 W5의 `score_tracker.py`를 잘못 import.

**원인**: 폴더명이 숫자로 시작하므로 각 게임의 `tests/conftest.py`가 자기 src를 `sys.path.insert(0, ...)`로 주입. pytest가 두 게임 테스트를 함께 수집하면 sys.path에 양쪽 src가 다 들어가고, 똑같은 모듈명 `score_tracker`는 sys.path 앞쪽이 먼저 잡힘 → 게임 간 cross-import 발생.

**해결**: W5의 `score_tracker.py` → `hunt_tracker.py`로 리네임, 클래스명 `ScoreTracker` → `HuntTracker`. game.py·테스트도 일괄 수정. 320 통합 회귀 통과.

**시사점 (W6 이후 강제 규칙)**:
- **모듈명에 게임 prefix를 붙인다**: W3 `score_state`, W4 `round_state`, W5 `hunt_tracker`. 평범한 이름(`score_tracker`)은 한 번만 써도 충돌 가능.
- 또는: 각 게임을 격리된 pytest invocation으로 돌리는 방법도 있지만, 통합 회귀의 가치가 크니 모듈명 격리가 정답.

---

### 문제 16 (W4 학습 자동 적용 성공): `-m` 모드 lazy import

본 회차의 `game.py`는 W4 트러블 #16 교훈으로 **함수 내부 lazy import 0건**. 모든 모듈 import는 파일 상단 `try: from .X / except ImportError: from X` 블록 한 곳에 집중. 추가로 `from core.vision.yolo_engine import YoloEngine`은 별도 try/except로 처리 (직접 실행 시 프로젝트 루트도 sys.path에 등록).

두 실행 모드 smoke 모두 통과:
- `python -m games.11_color_hunt.src.game` 
- `python games/11_color_hunt/src/game.py` 직접 실행 시 `core/` 경로 자동 보강

## W5 회고

### 잘 된 것 

- **W3·W4 인프라 100% 재활용**: theme/sound_manager 수정 0, ui_renderer는 W5 컴포넌트만 append. 신규 코드는 W5 고유 로직(YOLO 통합 + 미션·헌트 상태)에 집중.
- **친근한 UI 헬퍼**가 즉시 재사용 가능: `draw_rounded_panel`, `draw_color_dot`, `draw_progress_dots`, `_draw_medal`은 W6 이후 게임에도 적용 가능. core/ui 추출 시 가장 먼저 옮길 후보.
- **lazy import 금지 규칙이 처음부터 자동 적용**: W4 트러블 #16 교훈이 메모리·일별 로그에 남았던 덕에 본 회차 game.py는 처음부터 lazy import 0건으로 작성.
- **모듈명 충돌(트러블 #17) 빠르게 처리**: 320 회귀에서 즉시 발견 → 리네임 → 다시 통과까지 ~5분.
- **W4 마무리 직후 같은 날 W5도 마무리**: 같은 세션 내에서 두 게임 완료, 흐름 끊김 없음.

### 어려웠던 것 

- **YOLO 실기 검증 누락**: ultralytics 설치 여부, 모델 자동 다운로드, 노트북 GPU에서 30fps 유지 가능한지 등은 실제 카메라 환경에서만 확인 가능. 단위 테스트는 detector를 mock으로 대체했기 때문에 진짜 실기 성능 데이터는 없음.
- **dedup proximity 임계 80px가 매장 환경에 적정한가?** 카메라가 흔들리면 같은 객체 박스 위치가 80px 이상 변동 가능. 실기 후 튜닝 필요.
- **친근 도형 ↔ 분류 명확성 trade-off**: 둥근 모서리·광택은 친근하지만 객체 박스에서는 직선보다 약간 인식 어려울 수 있음. 실기에서 사용자 반응 확인 필요.

### W6부터 적용할 점 

1. **모듈명 게임 prefix 강제** (트러블 #17): 평범한 이름(score_tracker/state) X. W6은 `pose_*`, W7은 `dodge_*` 등.
2. **친근 도형 헬퍼는 core/ui 추출 1순위**: W6 K-Pop 댄스에도 둥근 진행 점·우승 메달 그대로 사용 가능.
3. **실기 검증을 별도 트랙으로 명시**: 코드 + 단위 테스트 완비 → "실기 환경 sanity" 단계를 일별 로그 체크리스트에 분리 (현재처럼 코드 마무리 후에 따로 잡는 게 안전).
4. **lazy import 금지 + 두 실행 모드 smoke**는 모든 게임 마무리의 강제 절차.
