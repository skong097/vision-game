## 친근 좀비 도형 — 본 회차 신규 컴포넌트

W4 Doby 얼굴(OpenCV 합성) + W5 친근 색 원 패턴을 응용. "친근하면서 살짝 무서운" 좀비.

| 부위 | 구현 |
|---|---|
| 본체 | `draw_color_dot`로 둥근 원 + 좌상단 흰 광택 + 검은 외곽 |
| 눈 흰자 | 흰 작은 원 2개 (눈 영역) |
| 눈 동공 | 짙은 빨강 (`ZOMBIE_EYE_COLOR = (0, 0, 60)`) 작은 원 |
| 입 + 이빨 | 짧은 검정 수평선 + 흰 수직선 3개 (이빨 패턴) |

3종 좀비:
- `normal`: 좀비 그린 `(90, 130, 80)`, 반지름 32
- `fast`: 보라 `(120, 90, 180)`, 반지름 26, 속도 1.6x
- `big`: 차콜 그레이 `(110, 110, 110)`, 반지름 48, 속도 0.8x

→ 색·속도·크기가 모두 다른 3종으로 다양성. 일관된 캐릭터 표현으로 친근감 유지.

### 회피 박스 시각화

핑크 둥근 외곽선 + 4 모서리 핑크 점. **충돌 임박**(좀비 중심이 박스 상단 100px 이내 + x 범위 겹침)일 때 박스 외곽이 노란색 깜빡임 → 사용자에게 "피해야 한다" 직관적으로 전달.

## W7 회고

### 잘 된 것 

- **누적 학습이 시행착오를 사실상 0으로**: W7 신규 트러블슈팅 없음. W3~W6에서 정리한 4개 규칙(`__init__.py` 삭제, lazy import 0, 모듈명 prefix, dual try/except)이 처음부터 자동 적용 — 메모리·일별 로그가 효과적으로 동작.
- **W3/W5/W6 패턴의 깔끔한 결합**: W3의 실시간 시뮬레이션(spawner + score_state), W5/W6의 친근 도형, W6의 Pose 처리가 한 게임에 자연스럽게 합쳐짐.
- **좀비 도형이 친근하면서도 분위기 살림**: 흰자+빨강 동공+이빨 세로선 패턴이 "할로윈"이라는 컨셉을 명확히 전달하면서도 위협적이지 않음.
- **time_provider 주입으로 dodge_state 25 case 모두 deterministic**: 시간 의존 코드를 단위 테스트로 완전히 커버.

### 어려웠던 것 

- **회피 박스 비율 (head_radius_ratio 0.45 등)이 매장 카메라 환경에 적정한가?** 본인 노트북 웹캠 거리(약 50cm) 기준으로 잡았는데, 매장은 보통 1~2m. 실기에서 박스가 너무 작거나 크면 비율 튜닝 필요.
- **Pose model_complexity=1 + 좀비 다중 렌더 FPS 미측정**: W6에서도 미측정. 좀비가 동시에 5~10마리 떠 있을 때 cv2.circle 다중 호출 + Pose 추론이 30fps에 영향 줄 가능성. 실기 1회로 확정.
- **YOLO 미도입 결정**: 기획서는 "Pose + YOLO 멀티 모달"이라 했지만 실제로 좀비를 가상 객체로 두면 YOLO가 자연스럽지 않음. 추후 매장의 실제 객체를 좀비로 인식하는 변형 게임(W10 AR 보물찾기와 결합)이 더 자연스러움.

### W8부터 적용할 점 

1. **친근 도형 헬퍼 core/ui 추출 시점이 점점 더 명확**: W3 ~ W7 모두 사용 중. W8 시작 전에 `core/ui/friendly_shapes.py` 추출 시도하는 게 합리적.
2. **회피/감지 박스 패턴 추출 후보**: W7 `body_tracker.DodgeBox`는 W4 face features와 합쳐 `core/vision/body_box.py`로 추상화 가능.
3. **time_provider 주입 패턴**: W5 hunt_tracker / W7 dodge_state 모두 동일. 단위 테스트 친화 표준으로 W8 이후 모든 상태 모듈에 적용.
4. **실기 sanity 트랙 분리 유지**: 코드 + 단위 테스트 마무리 → 카메라 환경 sanity는 별도 세션 (현재 패턴 유지).
