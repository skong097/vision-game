## W4 요약

이번 회차 핵심 결정:
1. **순수 함수/클래스 3종 + 통합 game.py** 구조를 W3 패턴 그대로 유지
2. **정확도 0~1 gradient** — 단순 정답/오답 대신 percent 표시 + 부드러운 EMA 게이지
3. **profile 기반 분류**: 각 표정에 `{feature: (low, high)}` 범위. `min(per-feature score)` 집계 → strict
4. **Doby 얼굴은 OpenCV 도형 합성** — sprite 없이도 표정 4종 시각화 (NanumGothic 이모지 X 박스 회피)

## Doby 얼굴 — OpenCV 도형 합성 결정

Sprite PNG 없이 표정 4종을 즉시 표현. 핵심 도형:

| 표정 | 도형 구성 |
|---|---|
| 웃음 | 점 눈 2개 + **위로 볼록 반원(입)** |
| 슬픔 | 점 눈 2개 + **아래로 볼록 반원(입)** + 처진 V자 눈썹 |
| 놀람 | **흰 큰 원 + 검은 동공(눈) + 세로 타원(입)** |
| 화남 | 점 눈 2개 + 짧은 수평선(입) + **찌푸린 V자 눈썹** |

→ `ui_renderer.draw_doby_face(frame, expression, center, radius)` 한 함수에서 모두 처리. sprite 디자인은 W4 마무리 이후 별도 트랙(W3 카페 sprite 미준비와 동일 결정).

## 측정 알고리즘 결정

W4 기획서는 "정확도 0~100% gradient"를 요구. 두 가지 후보:

| 방식 | 장점 | 단점 |
|---|---|---|
| **최고값 채택** (final = max accuracy) | 사용자가 한 번이라도 정확히 만들면 보상 → 보상감 큼 | 순간 우연 가능 (그러나 EMA 보정 후엔 거의 안 일어남) |
| 평균값 채택 | 측정 시간 내내 유지해야 점수 → 엄격 | 카메라 노이즈/순간 얼굴 가림에 취약 |

**채택**: 최고값 (`measure_best_accuracy`). 게이지 표시는 별개로 EMA(`alpha=0.35`)로 부드럽게 보간해 시각적 변동 억제.

코드 위치: `game.py:_finalize_round`

## W4 트러블슈팅

### 문제 14 (신규): conftest의 `face_features` import 순환 위험

**증상**: `round_state.py`가 `from .expression_classifier import GAME_EXPRESSIONS`를 하고, `expression_classifier.py`도 단독으로 작동. 그러나 `round_state`를 테스트할 때 `expression_classifier` 임포트 → 그 안에서 `face_features` 의존성이 없는지 확인 필요.

**확인**: `expression_classifier.py`는 `face_features`에 의존하지 않음 (`feature dict`만 받음). 따라서 순환 없음. round_state 테스트가 face_features까지 끌어오지 않으므로 단위 검증 깨끗.

**시사점**: 다음 게임부터 모듈 분리 시 **순수 모듈 간 의존 그래프를 단방향**으로 유지. game.py만 모두를 흡수.

---

### 문제 16 (실기 실행에서 발견): `render()` 안 lazy import 가 `-m` 모드에서 실패

**증상**: `.venv/bin/python -m games.02_emoji_face_battle.src.game` 실행 → 난이도 선택 + SPACE → MEASURE 페이즈 진입 첫 프레임에서 `ModuleNotFoundError: No module named 'face_features'` 크래시. 단위 테스트·smoke import는 통과했음 (게임 자체 import는 OK였고 render 내부 lazy import만 깨짐).

**원인**: `game.py:render()` 안에 카메라 입력 시 landmark 점을 그리려고 `from face_features import (MOUTH_LEFT, ...)` 를 함수 안에 박아둠. 패키지 경로 실행(`-m games.02_emoji_face_battle.src.game`) 모드에서는 `face_features`가 `games.02_emoji_face_battle.src.face_features`라 bare import 실패. 다른 모든 import는 파일 상단의 `try: from .X import / except ImportError: from X import` 패턴으로 보호됐는데 이 한 곳만 누락.

**해결**: 상수 9개(`MOUTH_LEFT, MOUTH_RIGHT, UPPER_LIP_CENTER, LOWER_LIP_CENTER, LEFT_EYE_TOP, LEFT_EYE_BOTTOM, RIGHT_EYE_TOP, RIGHT_EYE_BOTTOM, LEFT_BROW_INNER, RIGHT_BROW_INNER`)를 파일 최상단의 dual-import 블록으로 이동. render에서는 그냥 참조만.

**시사점 (W5 이후 강제 규칙)**:
1. **lazy/inline import 금지**. 모든 모듈 import는 파일 최상단 try/except ImportError 한 곳에 집중.
2. **smoke 실행 두 모드 모두 검증**: `python -m games.<NN>_<name>.src.game` 과 `python games/<NN>_<name>/src/game.py` 직접 실행. 단위 테스트만으론 -m 모드 path 차이가 잡히지 않음.
3. 단위 테스트만으로 catch 불가능한 클래스의 버그 (특정 페이즈만 실행되는 코드 path) → 실기 sanity 1회는 필수 절차로 포함.
