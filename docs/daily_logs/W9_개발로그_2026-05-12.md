## LLM 통합 설계 결정

### 1. claude-api 스킬 활용

W9 시작 시 `Skill(claude-api, ...)` 호출로 Anthropic SDK 통합 가이드를 받음. 결정 사항:
- **모델**: `claude-haiku-4-5` (vision 지원, 저렴/빠름, structured output 지원)
- **API**: `client.messages.create()` + `cache_control={"type": "ephemeral"}` + `output_config.format` json_schema
- **이미지**: base64 인코딩, JPEG/PNG/WebP 매직 바이트 자동 감지
- **에러**: 모든 anthropic 예외를 fallback으로 변환 (게임 끊김 방지)

### 2. Mock 패턴 — `client_factory` 파라미터

단위 테스트에서 anthropic SDK를 완전히 mock하기 위해 `evaluate_expression(..., client_factory=...)` 인자 추가. 기본은 `None` → `anthropic.Anthropic`. 테스트에서는 가짜 client 클래스 주입:

```python
factory = _make_factory(response_text='{"score": 85, "comment": "..."}')
r = evaluate_expression("강아지", b"\xff\xd8...", api_key="test",
                         client_factory=factory)
```

→ 네트워크/API 키 없이 27개 케이스로 LLM 통합 검증.

### 3. Fallback 우선 설계

- ANTHROPIC_API_KEY 환경변수 없으면 → fallback (50~70 랜덤 점수, "API 키 없음" 코멘트)
- API 호출 실패 → fallback ("평가 중 오류 발생 — fallback")
- 잘못된 JSON 응답 → fallback
- 빈 응답 → fallback

→ 매장 환경에서 API 키가 항상 설정되리란 보장 없으므로 게임은 어떤 경우에도 진행 가능.

### 4. 프롬프트 캐싱 한계 인지

Haiku 4.5는 최소 캐시 prefix 4096 토큰. 본 회차 system 프롬프트(평가 가이드 + 단어 풀 hints)는 ~1500 토큰 예상 → **silent miss 가능**. `cache_control` 자체는 무해(에러 X)고, 비용 영향도 미미(1게임 5호출 × Haiku 가격 → $0.01 미만). 일단 의도 명시 차원에서 추가, 추후 system 프롬프트가 늘면 자연스럽게 캐시 적중.

## W9 회고

### 잘 된 것 

- **claude-api 스킬이 정확한 패턴 제공**: 모델 ID(`claude-haiku-4-5`), vision 사용법, `cache_control` 위치, `output_config.format` 패턴 모두 문서화된 그대로 구현. 추정/추측 0건.
- **`client_factory` 주입 패턴이 강력**: anthropic SDK를 monkeypatch하지 않고 함수 시그니처에 `client_factory` 추가만으로 27개 케이스 단위 테스트 가능. 미래에 다른 LLM(예: Gemini)으로 swap할 때도 동일 패턴.
- **Fallback 우선 설계**: API 키 없는 환경에서도 게임이 끊김 없이 동작. 매장 환경 배포에 필수.
- **이전 학습 자동 적용**: W7·W8에 이어 3회 연속 트러블 0건. 누적 학습 효과 안정화.

### 어려웠던 것 

- **EVALUATING 페이즈 블록킹 호출**: cv2 윈도우가 ~2~3초 동안 멈춤 (스피너만 표시). 비동기 호출은 가능하지만 cv2 메인 루프와 호환 복잡. V1은 블록킹 + 회전 점으로 사용자에게 진행 중임을 시각 표시.
- **프롬프트 캐싱 silent miss 가능성**: Haiku 4.5 최소 prefix 4096 토큰을 system 프롬프트가 못 채울 가능성 큼. 비용 영향 미미라 그대로 진행했으나, 실기 검증 시 `usage.cache_read_input_tokens=0`이면 캐시 적중 안 됐다는 신호.
- **실기 검증 누락 (예상)**: API 키 설정 + 실제 카메라 환경에서 5라운드 플레이 검증은 별도 세션 필요. 단위 테스트는 mock이라 진짜 LLM 응답 품질은 측정 X.
- **단어 풀 10개 한계**: 더 많고 다양한 단어가 매장 재미를 키울 텐데, hint 작성 비용 + 캐시 효율(긴 system 프롬프트가 4096 임계 넘기 쉬움) trade-off. V2에서 확장 검토.

### W10 적용할 점 

1. **LLM mock 패턴 (`client_factory`)** 을 다른 LLM 사용 게임에도 적용
2. **새 의존성(anthropic) 격리 패턴**: 함수 내부 lazy import + fallback. 다른 외부 SDK 통합 시에도 동일.
3. **실기 검증 트랙 분리 정착**: 코드 + 단위 테스트 마무리 → 카메라 + API 환경 sanity는 별도 세션.
4. **프롬프트 캐싱 임계 인지**: 모델별 최소 prefix 토큰을 메모리에 저장. 미만이면 silent miss라는 사실 자체가 학습 가치.
