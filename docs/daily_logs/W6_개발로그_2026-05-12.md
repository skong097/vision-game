## 🐛 W6 트러블슈팅

### 🔧 문제 18 (사소): cross-pose similarity가 0.5보다 큼

**증상**: 최초 작성한 `test_t_features_score_y_pose_low`에서 T자 ideal feature가 Y자 profile에 0.62를 받아 `< 0.5` 단언 실패.

**원인**: Y자 profile의 `hand_y_off` 범위가 (-2.0, -0.55)로 넓음 (실전 Y 자세의 손 높이 폭). T자의 손 높이 0.0은 범위 경계에서 width의 0.38만큼 떨어졌고, fall-off가 1.0 - 0.38 = 0.62. 다른 feature(팔 각도)는 둘 다 폄이라 1.0. min 집계로 0.62.

**해결**: 단언을 `< 0.5` → `< NEUTRAL_THRESHOLD (0.70)`로 완화. **실전 의미**는 "분류 시 잘못 라벨링되지 않음"(임계 0.70 미만이면 NEUTRAL로 fallback). 그리고 별도 단언 `test_t_features_classified_as_t_not_y`로 classify_pose에서 정확히 T로 분류됨을 명시.

**시사점**: profile-based 분류기에서 cross-pose 점수가 0이 아닌 것은 정상. 핵심은 (a) NEUTRAL 임계 미만이거나 (b) classify의 best가 정답 포즈인 것.

- **Doby stick figure 즉시 동작**: 5종 포즈가 OpenCV 도형 합성으로 명확히 구분됨. sprite 없이도 사용자가 의도 즉시 이해 가능한 수준.
- **W5 친근 도형 헬퍼의 진가**: `draw_rounded_panel`, `draw_color_dot`, `draw_progress_dots`, `_draw_medal` — 모두 W6에서 그대로 호출. core/ui 추출 시점이 점점 더 명확해짐.
- **누적 회귀 393 cases 1.62s**: 6게임 통합 회귀가 여전히 2초 미만 — 단위 테스트 친화 설계 가치 확인.

### 어려웠던 것 😅

- **Pose 분류기의 cross-pose 분리도**: 트러블 #18처럼 ideal feature의 cross-pose score가 0.5~0.6 정도라 NEUTRAL 임계(0.70)에 의존. 실기에서 사용자가 어중간한 자세를 취하면 NEUTRAL로 떨어질 가능성. 캘리브레이션 시 NEUTRAL_THRESHOLD를 0.65 정도로 낮추는 옵션 검토 필요.
- **Pose `model_complexity=1` 실기 FPS 미측정**: refine 옵션이 없고 model_complexity만 0/1/2. 0이면 빠르지만 정확도 낮음. 본 회차는 1로 시작 → 실기에서 30fps 미달 시 0으로 변경 검토.
- **Doby stick figure 좌표 튜닝**: 5종 포즈의 팔 segment 좌표를 임의로 잡았는데, 실제 K-Pop 안무 미학과는 다를 수 있음. 디자인 트랙 별도.

### W7부터 적용할 점 🔧

1. **친근 도형 헬퍼 core/ui 추출 검토**: 5게임(W3·W4·W5·W6) 모두 `draw_rounded_panel`/`draw_color_dot`/`draw_progress_dots` 사용. W7 시작 전에 `core/ui/friendly_shapes.py`로 추출 시도가 합리적.
2. **Doby 캐릭터 통합 트랙**: W4 얼굴 / W6 stick figure가 같은 Doby. 두 표현을 `core/doby/` 모듈로 합치는 게 자연스러움.
3. **분류기 NEUTRAL_THRESHOLD 캘리브레이션 절차** 표준화: profile 자체보다 임계를 튜닝하는 게 안전 (실기 환경에 맞춤).
4. **실기 sanity step**을 코드 마무리 직후 별도 트랙으로 분리 — 본 회차도 코드+테스트+문서 마무리하고 카메라 환경은 후속.
